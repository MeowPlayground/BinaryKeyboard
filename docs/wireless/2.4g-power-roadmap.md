# CH592F 2.4G 接收器与低功耗预留方向

本文只定义后续开发边界和传输契约，不表示当前固件已经具备 2.4G 接收器功能。

## 电源状态

- `ACTIVE`：按配置运行高轮询率，优先输入延迟。
- `LIGHT`：保留 RAM 和配对参数，关闭 RGB、周期 ADC 与高频扫描，由 GPIO 唤醒；键盘端无线电可停止工作，USB 供电接收器持续监听。
- `DEEP`：键盘主控 Shutdown，RAM 不保留，只留下 GPIO 唤醒；唤醒后使用持久化地址、频道和密钥快速恢复私有链路。

2.4G 不需要维持标准 BLE 连接事件。接收器始终作为 USB HID 设备在线，因此优化后的 LIGHT 有机会明显低于当前 BLE LIGHT 的实测 1.4 mA；最终数值必须以接收器和键盘实物测量为准。

## DEEP 无感输入契约

2.4G DEEP 可以作为正式支持的无感唤醒目标，但必须由可靠协议保证，不能沿用“发一次就删除”的 BLE 事件模型：

1. GPIO 锁存唤醒键，键盘启动后建立完整物理键盘状态。
2. 使用已保存的设备地址、频道/跳频种子和会话密钥直接发起 Wake/Sync，不重新进入用户配对流程。
3. 每个状态包携带持久会话 ID 和递增序列号。
4. 接收器按序列号去重，并在 USB HID 报告成功提交后返回 ACK。
5. 键盘只有收到 ACK 才能提交本地状态并删除待发包；超时必须重试。
6. PRESS 与 RELEASE 使用相同可靠确认，重连后的第一包必须是完整状态快照。
7. 接收器在会话变化、超时或异常重连时先向 USB 主机发送全零报告，防止遗留卡键。

## 自适应轮询

- 活动输入阶段允许 1K/4K/8K 等高频模式。
- 短暂空闲后降低发包频率。
- 进入 LIGHT 后停止周期发包，由 GPIO 首键唤醒并启动快速 Sync。
- 接收器由 USB 供电，承担持续监听、去重、ACK 和 USB 状态清理，避免把待机成本留在 150 mAh 键盘电池上。

## 与 BLE 的产品边界

- BLE LIGHT 保持连接，可正式支持首键正常执行。
- BLE DEEP 必须经过手机系统重连，默认消费唤醒键，不承诺输入框焦点无感恢复。
- 2.4G DEEP 的链路和接收器均由本项目控制，可通过 ACK、重试和状态快照正式支持首键无感。
- 两种传输可以共用按键状态机，但不能共用“发送即成功”的传输完成条件。

## 开发顺序

1. 接收器 USB HID 与全零状态看门狗。
2. 固定频道的 Wake/Sync、序列号、ACK、超时重试和去重。
3. 完整键盘状态快照以及 PRESS/RELEASE 压力测试。
4. LIGHT GPIO 唤醒和实测平均电流。
5. DEEP Shutdown、持久会话恢复和首键延迟测试。
6. 最后再增加跳频、加密、多设备配对和自适应高轮询。
